## 这是什么

一个纯终端的电子宠物游戏，饲料是**麦当劳菜单上的真实餐品**。

你喂它吃麦乐鸡，它就会按照「7700 kcal ≈ 1 kg 脂肪」的营养学换算**真的长胖**；
你喂它吃巨无霸，它的钠摄入就会**真的往上飙**；
喂到一定程度，它会变异、会高血压、会死，死因和墓志铭都由真实数据决定。

```bash
python demo.py
```

不用装任何东西，不用配 Token，直接看它走完一生。

## 30 秒跑起来

```bash
git clone https://github.com/lucklyme/mcd-pet.git
cd mcd-pet
python demo.py                 # 看它走完一生
```

自己养一只：

```bash
python -m mcd_pet adopt               # 领养（名字随机）
python -m mcd_pet adopt 麦麦           # 或者自己取名字
python -m mcd_pet feed 麦乐鸡          # 喂它（支持模糊匹配：麦乐鸡 → 麦乐鸡5块）
python -m mcd_pet status               # 看状态卡
python -m mcd_pet recommend            # 该喂什么（按它当前健康值算）
python -m mcd_pet list 薯条            # 查饲料库
python -m mcd_pet wait 3               # 不喂，让它饿着
python -m mcd_pet forms                # 看全部 11 种形态
```

存档默认写在 `.mcdpet.json`，关掉终端也不会死（除非是饿死的）。

## 数字都是真的

饲料库是麦当劳 MCP `list-nutrition-foods` 接口的原始返回值，**158 个真实在售餐品**，没有一个是编的。

| 游戏数值 | 怎么算的 | 用的真实字段 |
|---|---|---|
| 体重增长 | `(kcal − 200/3) ÷ 7700 × 1000` 克 | `energyKcal` |
| 脂肪肝 | `− fat × 0.06` 健康 | `fat` |
| 高血压 / 钠中毒 | `− sodium × 0.0016` 健康 | `sodium` |
| 心情（糖分快乐） | `+ min(carb × 0.15, 12)` | `carbohydrate` |
| 健康回复 | `+ protein × 0.05 + calcium × 0.004` | `protein` / `calcium` |
| 饱食度 | `+ kcal ÷ 200 × 45` | `energyKcal` |

所以「喂一个巨无霸胖 58 克」是可验证的：513 kcal 减去猫每回合约 67 kcal 的基础代谢，
余下 446 kcal 除以 7700，就是 57.9 克。

## 死因与墓志铭

| 死因 | 条件 | 墓志铭 |
|---|---|---|
| 钠中毒 | 累计钠 ≥ 8000 mg | 它一生摄入 X mg 钠，肾脏表示理解但不接受 |
| 脂肪肝 | 累计脂肪 ≥ 300 g | 它吃下 X g 脂肪，肝脏选择了提前退休 |
| 撑死 | 撑着的时候倒下 | 最后一餐是「X」，它说还想再来一口 |
| 饿死 | 饿到健康归零 | 它等了你 X 个回合，你一次都没回来 |

死因判定优先报「有数据支撑」的那一种——毕竟「它吃了 8920 mg 钠」比「它吃多了」有说服力得多。

## 两种数据源

```bash
python demo.py            # 离线快照，零 Token 直接跑
python demo.py --live     # 实时走麦当劳 MCP
```

实时模式只从环境变量读 Token，**不落盘、不入库**：

```bash
export MCD_MCP_TOKEN=你的Token
python demo.py --live
```

实测两条路径结果完全一致（158 个餐品、同一个结局）。
